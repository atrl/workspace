# 美股标准结算日期映射合同与来源边界

`src/data/settlement_value_dates.py::standard_value_dates` 是小型数据合同工具，不构造或认证历史日历。输入必须包含连续自然日的结算状态（true/false/unknown）和带生效日的结算周期。周期按交易日选择；从交易日之后开始数可结算日。交易日自身可以是结算系统不提供服务的日子，不强行将交易日历与结算日历合并。遇到未知、周期无覆盖或日历尾端不足即拒绝，不跳过未知继续猜测。

## 为什么不能使用交易所开市日替代

1. [DTCC 2025-01-08通知21340-25](https://www.dtcc.com/-/media/Files/pdf/2025/1/8/21340-25.pdf)说明2025-01-09全国哀悼日股市关闭，但DTC/NSCC/FICC照常清算结算此前交易。使用交易所日历会将2025-01-08普通T+1交易错误推迟。
2. [DTCC通知20703-24](https://www.dtcc.com/-/media/Files/pdf/2024/9/11/20703-24.pdf)说明2024-10-14不提供结算服务。正常T+1的2024-10-11交易不能据股市开放而结算在10月14日。
3. [Good Friday 2024通知19835-24](https://www.dtcc.com/-/media/Files/pdf/2024/3/8/19835-24.pdf)列出2024-03-27的T+2结算为4月1日；DTC有限开放不等于普通股票标准结算日。
4. [SEC T+1实施公告](https://www.sec.gov/newsroom/press-releases/2024-62)规定2024-05-28切换。合同测试中显式提供Memorial Day假日：5月24日交易按T+2、5月28日交易按T+1，均落在5月29日，不能按结算发生时的周期反推旧交易。

以上来源区分市场交易、DTC设施开放和具体结算服务。已搜索到2023–2026年度anticipated schedules，但部分原PDF直接下载返回404；未完成原件视觉核对及所有例外公告核验。因此本轮没有创建一个声称完整合格的2023–2026结算日历，搜索索引摘录不替代完整数据验收。PDF技能只用于确定读表/脚注要求，未将下载失败的HTML误当PDF使用。
