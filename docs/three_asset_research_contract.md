# SOXL / SOXX / cash 持续研究与独立评估合同

本合同落实2026-10-15用户确认的研究计划。状态入口为
`research/three_asset_campaign.json`；实验仍以各自notebook、冻结plan和Qlib
Recorder为证据权威。本文件不替代旧卡、不重建全仓库索引、不授予生产晋升。

## 目标和权限

持续分析失败原因、比较全部超额和落后区间，再通过有依据的单机制实验优化。
交易资产仅SOXL/SOXX/cash，只做多、无融资、权重和为1。允许模型、配置与执行
重构；旧SOXL≤30%、cash≥15%是可检验结构，不是本轮用户硬约束。
最大回撤30%的验收不放宽。不购买数据、不真实下单、不替换现役release。

|角色|责任|边界|
|---|---|---|
|研究负责人|保持Goal、优先级、失败记录、下一实验和Git交付|不能迁就结果改变门槛；不能用单支线缺数据结束整个目标|
|研究执行者|归因、机制、实现、训练、原生账户与notebook|不能自己签发晋升；不能事后选择窗口、seed或弱对照|
|独立评估者|从冻结设计及原始证据开始，事前审设计、事后核验|只读候选；不调参、不扩大无关审计；列具体门禁及最小缺口|

评估者使用独立上下文；角色分离不能消除共同模型偏差，更不能生成新的市场证据。
负责人保留评估原文及其针对的计划/源码/Recorder身份，修复后只复查受影响项。
评审交接后，负责人必须核对执行代理或进程的实际状态；已结束的代理需要显式
启动下一任务，普通排队消息不代表运行。运行中使用已确认的原句柄观察，不因
观察超时重启；任务文件、锁或计划状态不能替代活跃执行证据。

## 研究循环与实验合同

失败归因 → 全部胜负区间比较 → 决策时可用信息检验 → 冻结单机制 → 设计评估
→ 训练/原生账户 → 结果评估 → 更新下一行动。每轮一个机制和有限候选预算。

每份计划记录父实验、差异机制、经济理由、数据及模型身份、可用时间/标签成熟
时间、训练/选择规则、拟合及账户上限、同条件对照、费用、门禁和失败条件。
记录实际尝试及历史使用；变更notebook名称不重置多重检验或研究选择历史。
过去尝试数无法恢复时明确未知，不能声称已完整校正所有搜索。

开发反馈允许改进；任何被用于选择或改造的区间都转为已使用研究数据。
年度/季度/126日窗口全部报告；2026等不完整年度单列，不用于完整年度通过率。
事后胜负标签仅用于归因。可交易状态只能使用决策前可见信息；账户风控状态和
市场状态分别标注，不把它们当作相同或独立的观测。

会计贡献不等于可实现反事实。控制器消融会改变后续持仓及风险路径，差异应标明
是完整机制包的效果。每次都保留SOXX、匹配对照及既有强参考；风险/暴露匹配
对照只帮助解释，不能替代直接SOXX验收。复用未变化的已核验模型和账户。
强参考必须逐实验预登记身份及可比风险资格；高风险旁路仅作诊断，不自动变成
要求候选击败的合格强参考，也不能事后改选较弱对照。

## 验收与前向

新研究采用10万美元起点、显式冻结的IBKR Pro Tiered费用投影、独立0/2/5bp滑点
账户。费表是研究假设，非逐年券商账单；旧10/25bp证据保持原身份。

全部成本均要求：净相对SOXX财富>1（保留既有数值容差）、超越匹配对照与
预登记强参考、收盘及可用盘中监控最大回撤≤30%、CVaR5不劣于SOXX、完整年度
正超额比例≥70%、126交易日滚动正超额比例≥70%。缺失全年、分钟或真实派息
认证不可用摘要代替；现有研究价格/监控口径的限制随结果保留。

区块置信检验在实验前冻结：承接近期平均63日stationary bootstrap、2000次重采样、
固定seed20261014，以SOXX和配对对照为比较，alpha=0.025；若一轮有多个候选，
按候选数进一步校正。需要下界为正；该校正不覆盖未知的历史研究选择。
新机制若依赖不同统计合同，须在看结果前说明并由评估者核对，不为失败换检验。

历史门通过仅产生候选。完整决策规则、模型、来源与成本身份冻结后取得独立
shadow/paper证据；至少60完整配对日、各预登记市场状态15日及3次转换只是最低
观察条件。126日滚动和年度资格需实际足够的新观测，不因60日达到便签发通过。
前向状态定义、观察频率及统计评估时点在候选启动前冻结，避免每天重复检验直到
偶然通过。前向不足为继续观察；不借旧模拟盘天数，不重命名旧历史。

历史训练、历史回测和有依据的失败归因不以最新行情或合格前向天数为启动条件。
重复使用的历史标为开发/诊断，不能冒充独立验证；单个前向观察等待交易时段，
不能据此阻塞整个历史研究目标。连续轮询次数本身也不能证明研究无路可走。

研究可与冻结观察分开进行，新版本不继承旧版本资格。运行监控记录信号延迟、
漏执行、持仓偏差及实际费用，区分模型失效和实现错误。总Goal完成要求独立
评估确认历史与充分前向证据均通过，软件通过或负实验归档均不算达成。

## 状态和最小交付

单实验可为设计待审、执行中、研究完成/不晋升、历史候选待前向或证据不足。
单支线needs_data不代表总Goal blocked；先检查是否仍可推进有依据的新机制。
整体blocked仅按Goal工具的连续阻塞规则记录具体依赖，用户恢复后重新检查。
不能因失败而无依据重复参数搜索，也不能以重复审计替代研究。

新增分析从research notebook开始；大对象留Recorder/NAS，根目录只保留瘦卡。
沿用原生Qlib API、已存在的聚焦测试和一次必要读回。不为文档增加测试，不为
Git交付重训。负责人只提交本轮文件并推送main，保留无关WIP。
