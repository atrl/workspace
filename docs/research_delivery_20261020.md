## 消耗判断

此前对本线程 rollout 的一次 1,408 条 usage 记录快照为：输入 319,781,844，
其中缓存输入 314,906,880；输出 881,846，其中推理输出 497,312。
非缓存输入为 4,874,964。缓存输入、推理输出都是子项，不能再次加到总数。
这是此前观测的累计 usage，不是交付时最新计数，也不是账单。
Goal 的约 1,270 万 token 与 rollout 使用不同口径，不能混加。
现有记录不能可靠分摊到每个工具、角色或真实模型账单，未声称具体节省金额或比例。

约 98.5% 的输入 token 在缓存子项中；后续应减少主线程携带的历史内容及重复工具输出，
而不是仅看表面总 token。任务包目标不超过 8k token、常规工具输出不超过 2k、
回报不超过 800 字；监控不读取历史对话和模型。反复兼容修复仍是实际返工成本，
本次缓存恢复避免了再次训练，但不能称恢复过程零消耗。

`aggregate_usage`按 response_id 去重并正确处理累计计数，每次明确扫描指定日志。
同类任务比较非缓存输入、输出、调用次数、修复次数和已知模型角色，不降低科学门槛。
