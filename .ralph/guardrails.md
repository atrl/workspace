- Read `codex_exec_plans/active/2026-04-10-soxl-agent-loop.md` before choosing the next step
- Work on `SOXL` only
- Prefer one meaningful loop step per rotation:
  - one validation run, or
  - one harness improvement, or
  - one production-layer improvement with verification
- Do not re-implement already-finished promotion-gate or broker-adapter plumbing unless a concrete bug is found
- Prefer validating the isolated balanced walk-forward harness before further cap/reward tuning
- Update repo proof-of-work before finishing a rotation:
  - active plan
  - `memory/2026-04-13.md`
- Prefer `src/soxl_quant/` over ad-hoc top-level scripts
- Keep signal generation, sizing, broker execution, and reconciliation clearly separated
- Do not use destructive git commands
- For real quant validation in this repo, use `qlib_venv/bin/python` unless the shell `python3` has been explicitly reprovisioned; on 2026-04-13 the base `python3` is `3.14.3` without `qlib`
- Do not treat `--profiles smoke --smoke --walk-forward` as a substitute for balanced late-period evidence; on 2026-04-13 the seeded smoke walk-forward screen only persisted `wf_2020`, so use smoke for fast direction screening and balanced for real `wf_2023_2024` verdicts
- When validating promotion after isolated walk-forward, read `artifacts/models/soxl_balanced_summary.json` for the verdict; `wf_*` worker summaries are debugging artifacts and can contain incomplete fixed-split promotion fields such as `Infinity`
- For temporary smoke config experiments, snapshot `artifacts/models/soxl_smoke_summary.json` to a uniquely named file immediately after the run; the next smoke run will overwrite it, and the summary may still report `walk_forward_evaluated = true` with missing `wf_2023_2024` values as `-Infinity`
- For balanced seeded promotion checks, do not expect a populated top-level `walk_forward` block in `artifacts/models/soxl_balanced_summary.json`; the pass/fail evidence is persisted under `promotion.walk_forward.checks`, so read that block or the final printed summary instead
- For balanced `curve_power` tuning near the linear baseline, test intermediate values before more extreme ramps; on 2026-04-13 `0.75` beat both `1.0` and `0.5` on the late-window/full-return trade-off, so interpolation around the best candidate is more valuable than jumping straight to harsher shapes
- For balanced cap-shape interpolation above the current winner, do not assume moving back toward `1.0` is safer; on 2026-04-13 `curve_power = 0.875` recovered some full-run return versus `0.75` but worsened `wf_2023_2024` from `8.2% / 0.17` to `6.6% / 0.15`, so compare against the current best candidate directly, not just the linear baseline
- For balanced cap-shape interpolation above `0.75`, do not assume the region is smooth just because fixed-split metrics stay near baseline; on 2026-04-13 `curve_power = 0.8125` kept fixed split near the `0.875` result but crashed `wf_2023_2024` to `-8.2%` and blocked promotion, so midpoint probes still need the full balanced walk-forward verdict
- For balanced cap-shape interpolation just above the current `0.75` winner, do not assume a tiny move back toward linear is a safe compromise; on 2026-04-13 `curve_power = 0.78125` recovered only about `4.1` points of full seeded return versus `0.75` but cut `wf_2023_2024` from `8.2%` to `2.0%`, so very fine upper-side probes still need the same late-window filter
- For balanced cap-shape interpolation below the current winner, do not trust fixed-split parity alone; on 2026-04-13 `curve_power = 0.6875` kept fixed split near `0.75` (`359.6%` vs `361.2%`) but flipped `wf_2023_2024` from `+8.2%` to `-2.1%` and blocked promotion, so the late walk-forward sign is the deciding filter
- For balanced timing tweaks around the current `curve_power = 0.75` winner, do not assume earlier cap engagement helps just because delayed starts looked weak in smoke; on 2026-04-13 moving `start_drawdown` from `0.10` to `0.08` kept promotion eligible but degraded `wf_2023_2024` from `8.2%` to `5.8%` and cut full seeded return from `361.2%` to `350.1%`
- For balanced timing tweaks around the current `curve_power = 0.75` winner, do not assume later cap engagement is a safe way to recover return; on 2026-04-13 moving `start_drawdown` from `0.10` to `0.12` improved the full seeded result from `361.2%` to `371.2%` but collapsed `wf_2023_2024` from `8.2%` to `0.6%`, so the late walk-forward window should stay the deciding filter
- For balanced floor-timing tweaks around the current `curve_power = 0.75` winner, do not assume a tighter `full_drawdown` is a safer version of the same idea; on 2026-04-13 moving `full_drawdown` from `0.30` to `0.25` kept the fixed split inside the gate but flipped `wf_2023_2024` from `+8.2%` to `-7.1%` and blocked promotion
