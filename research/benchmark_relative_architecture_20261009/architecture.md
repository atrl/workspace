# SOXX 相对架构与本轮边界

目标是取得成本后、跨窗口且能经受新数据检验的 SOXX 超额。当前没有足够证据证明已实现。此次保留 Qlib 数据与回放基础，将有限专家、成熟反馈、组合分配、实际成交和晋升判断分开；只验证 fixed-share 在线更新这一项变化。固定参数与运行范围均在 [plan.json](plan.json)，依据见 [research_sources.md](research_sources.md)。

## 当前可复用基础与已排除路线

| 现有能力或证据 | 架构处理 |
| --- | --- |
| `src/model/integrated_allocation.py` 已有真实费用与相对 SOXX 组合目标 | 复用经核验的结算合同；不能把相对目标或扣费本身包装成新 alpha |
| `src/model/sparse_holdings_net_excess.py` 已有四专家、真实持仓与精确 hold | 本轮新增的是成熟反馈驱动的在线权重更新；与训练型专家 gating 区分 |
| `src/workflow/stage1_low_frequency_execution.py` 已有最小调仓控制 | 保留执行层边界；不同时搜索调仓阈值来改善本轮结果 |
| [风险预算诊断](../strategy_bottleneck_risk_budget_20261008/conclusion.md) 未支持单独加波动上限实现稳定超额 | 风险缩减只作为风险证据；不沿失败路线追加窗口或阈值网格 |
| [purged checkpoint 诊断](../purged_checkpoint_validation_20261008/conclusion.md) 经常退回 SOXX，未证明主动模型有效 | 保留 SOXX 空模型与严格标签成熟；减少主动交易不能自动解释成学习到了 alpha |

## 模块依赖方向

```text
canonical snapshot / provider manifest
  → src/data：qlib.init + D / Dataset 读取与时点审计
  → src/model：有限专家输出、成熟反馈、在线权重状态
  → src/backtest：实际持仓与费用结算、Qlib 原生回放及对账
  → qlib Recorder：完整输入、状态、持仓、报告、来源身份
  → src/analysis：同成本基准比较、逐期稳定性、风险与证据等级
  → notebook + slim sidecars：中文结论与晋升决定
```

`src/workflow` 只负责上述步骤的编排、冻结计划绑定和 fail-closed 检查。模型不读取评价区间的汇总表现；分析层不能反向改模型、专家或执行参数。dashboard、schedule 和 paper adapter 以后只消费 Recorder 登记的固定导出，不读取 notebook 内部状态。

## 本轮最小实现

1. 固定包含显式 SOXX、杠杆和防御方案的有限专家集合。每个专家拥有独立持仓和成本账本，含义与参数写入计划。
2. 在线分配只读取决策时已经成熟的专家净收益反馈。信号时点、反馈成熟时点和实际成交时点分别保存，不能以一个日期字段代替。
3. fixed-share 更新形成主账户目标；固定混合对照保持相同专家和初始混合，移除在线更新。两者均使用同一数据、费用与执行合同。
4. 主账户按真实持仓独立结算。费用、漂移与混合切换必须反映在主账户路径中；不能加权专家净值代替成交回放。
5. 通过原生 Qlib report 与独立账本对账后，再计算同成本 SOXX 相对财富、逐期超额、回撤、尾部风险与换手。实现正确与存在超额分别判定。

本轮不训练新增网络，不搜索学习率、专家权重、更新频率或阈值。归档全部专家及对照，不能根据历史结果替换主候选。

## 后续机制优先级

| 顺序 | 独立假设 | 启动条件 |
| --- | --- | --- |
| 本轮 | fixed-share 成熟净反馈能改善同专家固定混合 | 参数、对照、时点与评价合同先冻结 |
| 下一项 | 预测不确定性惩罚使主动权重合理收缩到 SOXX | 先取得可信、成熟的 OOS 校准证据；本轮不训练 uncertainty-aware optimizer |
| 后续 | 多情景主动风险约束能降低 regime 误判代价 | 情景估计只用过去数据，并与普通协方差作独立对照 |
| 后续 | 依据预测衰减平滑交易能改善净收益 | 先验证预测持续性；与已有调仓控制明确区分 |

任何一项都可以被 SOXX 基准否定。每次只登记一个机制变化，避免在同一段历史上连续修补直至出现赢家。

## 冻结协议与前向证据

- 执行前固定 `plan.json`，绑定 provider、数据截止、源码、专家、成本、状态初始化、评价窗口和随机化诊断设置。未观测日期不得用日历边界冒充价格样本。
- 使用未来特征/价格扰动不改变此前目标、成熟时点、实际费用、SOXX 空模型和原生 Qlib 对账验证因果与执行合同。缺数据或对账失败时停止，不降级为 pandas-only 回测。
- 历史诊断完整报告主候选与对照，不选择最有利成本、年份或起点；不把工程测试通过解释成科学目标通过。
- 新数据必须先通过来源、复权和可用时点审计，并形成新的 canonical snapshot/provider 版本。补齐旧数据不等于取得从未使用的前向证据。
- 冻结后将每次决策输入、状态、目标和时间戳追加归档，再接收后续真实市场结果。等计划要求的连续证据与风险门满足后，才能另建 validated card，再讨论 production paper/sim；本卡不自动晋升。
- 若查看前向结果后改变参数，旧版本证据保留，新版本重新开始独立证据区间。研究失败不触发自动扩大搜索。

## 产品与数据边界

现金收益在本轮固定为零，不能据此推断真实现金账户表现。SOXL 是每日杠杆产品，不是 SOXX 的长期三倍组合；不以合成杠杆收益延长样本。当前价格历史的复用、复权口径和信息可用时点限制应在 `summary.json` 与中文结论中保留。

主 notebook、计划、摘要、结论和小型分析表保留在卡根目录；专家路径、主账户持仓、反馈矩阵、原生组合报告与大预测文件进入 Qlib Recorder。运行结果由已执行 notebook 和 `summary.json` 提供，本文只描述研究设计。
